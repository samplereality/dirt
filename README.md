# Dirt — Bury the Web

A creative digital work by Mark Sample. On any web page, the reader taps a button and shovelfuls
of dirt bury the lower third to half of the page; then a biome grows over it, chosen at random:
a flower garden, a meadow, vines up the edges like a trellis, a hedgerow, a forest on dark loam,
or cacti on sand. Revisit a buried page and the garden is still there. Mobile-first.

**Phase 1 (feasibility)** is complete: see **[FINDINGS.md](FINDINGS.md)** for what worked, measured on
an iPhone and across three desktop browsers. **Phase 2** is under way, extension-first: see
**[PHASE2.md](PHASE2.md)** for the feature list (all seven features are in), decisions made,
decisions pending, and the device checklist for the next build. **[CLAUDE.md](CLAUDE.md)** is
the hand-off brief for working on the code with Claude Code.

## Layout

| Path | What |
|---|---|
| `dirt-core.js` | The whole piece: one dependency-free module (`Dirt.start()` / `stop()` / `stats()` / `export()` / `restore()` / `checkpoint()` / `resume()` / `share()`). Every delivery route injects this same file. |
| `spike-0-core/` | Heavy test page + Playwright benchmark harness; its README documents how the core works. |
| `spike-b-safari-web-extension/` | Manifest V3 Web Extension (Safari / Chrome / Firefox): **the product.** Saves and restores gardens, album, share, dirt that follows links. |
| `spike-a-ios-action-extension/` | Safari share-sheet Action extension, "Bury with Dirt": the quick entry on iOS, bundled in the same app; cannot save gardens. |
| `spike-c-in-app-browser/` | WKWebView browser + share extension. Retired in Phase 2; still builds as the iOS host app's shell. |
| `spike-d-web-fallback/` | Paste-a-URL website: iframe when allowed, else server-side screenshot. The no-install demo. |
| `ios/` | XcodeGen spec that assembles the host app and the three extension targets from the spike folders. |
| `dist/` | Generated by `build.sh`: store-ready `chrome/` and `firefox/` copies of the extension (committed). |
| `tests/` | Headless Playwright checks for the core and the extension (`npm test`); see its README. |
| `docs/` | Screenshots: one per biome, plus the Phase 1 fallback page. |
| `build.sh` | Regenerates everything derived from `dirt-core.js`: the extension copy, `dist/`, and the inlined `Action.js`. Run after every core edit. |

## Quick start

```sh
npm install          # Playwright for the harnesses (pinned to the preinstalled Chromium)
npm run serve        # Spike 0 test page at http://localhost:8080/spike-0-core/test-page.html
npm run bench        # headless iPhone-emulated benchmark
npm run fallback     # Spike D at http://localhost:8787
npm test             # headless checks (core + extension), ≈ 8 min
sh build.sh          # after editing dirt-core.js
```

Desktop extension: `sh build.sh`, then load `dist/chrome/` (chrome://extensions, Developer mode,
Load unpacked) or `dist/firefox/manifest.json` (about:debugging, Load Temporary Add-on).

iOS: `brew install xcodegen && cd ios && xcodegen generate && open Dirt.xcodeproj` (see `ios/README.md`).

## Principles

- Dirt never reads or changes the host page; it only draws on top of it, in a Shadow DOM, on canvas.
- No data collection, no network requests. The module stores nothing; the extension keeps gardens, thumbnails and the album in its own `storage.local`, on the device.
- Nothing ties the project to a specific Apple Team ID; signing lives in an untracked `Config.xcconfig` value.
