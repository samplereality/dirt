## What this is

"Dirt" is a creative work by Mark Sample: on any web page, shovelfuls of
dirt bury the lower third to half of the page, then a garden grows over it. One dependency-free
module, `dirt-core.js`, does everything on screen. It is delivered as a Manifest V3 browser
extension (Chrome, Firefox, Safari on macOS and iOS; `spike-b-safari-web-extension/`), as an iOS
share-sheet action (`spike-a-ios-action-extension/`) bundled in the same iOS app (`ios/`), and as
a no-install web demo (`spike-d-web-fallback/`). `spike-c-in-app-browser/` is retired but still
builds. The branch history is in `git log`; commit messages carry the design reasoning.

## Hard rules (Mark's, do not relax)

- The core never reads or changes the host page. It draws on top of it, in a Shadow DOM, on
  canvas, `pointer-events: none` except its own corner buttons. The only exception, in the
  extension's content script, is reading `document.title` once as the album label.
- No analytics, no network requests, nothing leaves the device. Gardens and thumbnails live in
  the extension's `storage.local` only.
- Nothing ties the project to an Apple Team ID: signing lives in gitignored `ios/Local.xcconfig`.
- Keep App Store guideline 4.2 (minimum functionality) in mind for the iOS app: it bundles real
  extensions, not just a web view.
- The dirt is never more than half the page (`fill` default `[0.33, 0.5]`); it never spreads
  upward; no towers or pillars, mounds and heaps only.

## Working on the core

- `dirt-core.js` is plain ES2017 inside an IIFE, no build step, so the same file can be inlined
  into a `<script>`, a Safari preprocessing file, a content script or a `WKUserScript`. Keep it
  that way: no modules, no modern syntax the Safari 16.4 content-script world would choke on.
- After every edit to `dirt-core.js` run `sh build.sh` and commit what it writes: the copy in
  `spike-b-safari-web-extension/extension/`, the inlined `Action.js` for the share-sheet action,
  and `dist/chrome/` and `dist/firefox/`. The Xcode project builds from those committed files.
- Sections of the file, top to bottom: options (`DEFAULTS`) → palettes and `BIOMES` → dirt
  phase (`spawnShovel`, `arcClear`, `land`, `steepSide`, `stepParticles`, `settle`, `stepBury`)
  → flora systems (`FLORA`, one entry per biome: flowers, grass, vines, bushes, trees, cacti) →
  groundcover → growth loop → resize/replay of the display list → export/checkpoint/restore →
  share/picture → `API` (`Dirt.start/stop/toggle/stats/ping/share/picture/export/restore/
  checkpoint/resume`, `Dirt.phase`).
- Timing: the sand simulation ticks at `simHz` (30) under a 60 fps render; `buryMs` and
  `growMs` are targets the routine paces itself toward on real time, so nothing is seed-
  reproducible. That is why saved gardens store the scene (display list + soil profile), not
  a seed.
- `rnd()` is a xorshift on the module-wide `seed`; `settle()` steps the same variable with an
  LCG and must use its high bits (`seed >>> 16`) for decisions, the low bits barely vary.
- The feel of the throw and the slopes took several rounds of device feedback; the current
  state and its tuning knobs are described in `PHASE2.md` ("Feel of the throw") and
  `spike-0-core/README.md` ("Feel"). Change them with `node tests/run.mjs core-settle core-bury`
  open, and look at `tests/out/bury-*.png`, not only the numbers.

## Working on the extension

- Source is `spike-b-safari-web-extension/extension/` (also what the Safari target copies).
  `dist/chrome/` and `dist/firefox/` are generated by `sh build.sh` because the two browsers
  want different manifest keys; never edit `dist/` by hand.
- Files: `background.js` (click handler, storage, album index, spill budget, capture),
  `shared.js` (content-world helpers: `DirtExt`), `inject.js` (what a click runs),
  `autorestore.js` (what page load runs on allowed sites), `album.html/css/js`.
- Messages between content world and background are listed at the top of `background.js`
  (`dirt:save`, `dirt:begin`, `dirt:checkpoint`, `dirt:lookup`, `dirt:forget`, `dirt:list`,
  `dirt:thumb`, `dirt:album`, `dirt:capture`, `dirt:spill-state`).
- Permissions are `activeTab`, `scripting`, `storage`, `unlimitedStorage` plus optional per-site
  access requested inside the click. Do not add `<all_urls>` or `tabs` at install; Mark wants
  no scary store warning and a simple privacy note.
- Chrome refuses `captureVisibleTab` without `activeTab` or `<all_urls>`; a per-site grant is
  not enough. The core's garden-alone picture is the fallback and is intended.
- `shared.js` is declared with `var` so it can be injected twice into the same world.

## Testing

```sh
npm install            # Playwright 1.56.1, pinned; uses the Chromium it bundles
npm test               # tests/run.mjs: every check, ≈ 8 min, PASS/FAIL per script
npm run test:core      # core only;  npm run test:ext  # extension only
npm run serve          # http://localhost:8080/spike-0-core/test-page.html to watch it by eye
npm run bench -- --biome forest --shots tests/out/forest   # fps numbers + timed screenshots
```

`tests/README.md` explains each script and the headless pitfalls (service-worker CSP forbids
`new Function`; `tabs.query({url})` ignores ports; the per-site permission prompt cannot be
clicked headless, so tests pre-grant `localhost`). Playwright screenshots are the main review
tool for the look of the dirt; open the PNGs. On macOS `npx playwright install chromium` has
hung before; `PW_CHANNEL=chrome` (Spike D) or the bundled Chromium path work around it.

What cannot be tested here and needs Mark's iPhone or a desktop browser: the per-site permission
prompts, the Safari share sheet, rotation on a real device, Web Share. The device checklist is
in `PHASE2.md` ("Device checklist for the next build").

## Conventions

- Prose in docs and commit messages: plain, no marketing. Commit messages explain the why; the
  body is the design record. Keep `PHASE2.md` current when a feature's status changes.
- Edit Markdown with the Edit tool or a Python string replacement, never `sed -i` with `a\` or
  `s` on these long-line files: two earlier commits corrupted `spike-0-core/README.md` that way
  (a bullet inserted after every character) and it had to be rebuilt from history.
- Scratch files, screenshots and test output go to `tests/out/` (gitignored), not the repo root.
- Do not bump `VERSION` in the core for feel changes; bump the extension's `manifest.json`
  version when extension behaviour changes (0.6 now).
